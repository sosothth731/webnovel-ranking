# 웹소설 랭킹 TOP15 자동 수집기

카카오페이지 / 리디북스 / 네이버시리즈 3사의 로맨스 랭킹 1~15위를
작품명·작가명·론칭일·지표(뷰수/다운로드수/별점)·키워드로 정리해 CSV로 저장합니다.
매일 실행하면 날짜별로 계속 쌓여서 순위 변동 추적이 가능합니다.

## 1. 준비물

- Node.js 18 이상
- (선택) GitHub 계정 — 매일 자동 실행을 원하면 필요

## 2. 로컬에서 실행하기

```bash
npm install
cp .env.example .env
```

`.env` 파일을 열어 `KAKAO_RANKING_API_URL` 값을 채워주세요. **이 값은 직접 캡처해야 합니다** (아래 3번 참고).
리디북스·네이버시리즈는 별도 설정 없이 바로 동작합니다.

```bash
npm run collect
```

실행하면:
- `output/webnovel_ranking.csv` — 실행할 때마다 계속 누적되는 전체 이력 파일
- `output/daily/YYYY-MM-DD.csv` — 그날 하루치만 담긴 스냅샷 파일

두 개가 생성/갱신됩니다.

## 3. 카카오페이지 API 주소 찾는 법 (최초 1회만)

카카오페이지는 페이지가 브라우저에서 자바스크립트로 그려지는 방식이라, 서버가 그냥 HTML만
받아와서는 순위 데이터를 얻을 수 없습니다. 실제 데이터가 오는 API 주소를 한 번 캡처해서
`.env`에 넣어줘야 합니다 (네이버시리즈 조사할 때 하셨던 것과 같은 방법입니다).

1. 크롬에서 `https://page.kakao.com/landing/ranking/11/89/` 접속
2. `F12` → **Network** 탭 → **Fetch/XHR** 필터
3. 페이지 새로고침
4. 요청 목록에서 이름에 `ranking`이 포함된 요청을 클릭
5. 오른쪽 **Headers** 탭의 **Request URL** 전체를 복사
6. `.env`의 `KAKAO_RANKING_API_URL=` 뒤에 붙여넣기

이 값은 랭킹 카테고리가 바뀌지 않는 한 계속 유효합니다.

## 4. 매일 자동 실행 (GitHub Actions)

1. 이 폴더를 GitHub 저장소에 올립니다 (private 저장소 권장).
2. 저장소 **Settings → Secrets and variables → Actions**에서
   `KAKAO_RANKING_API_URL` 이름으로 시크릿을 하나 추가하고, 3번에서 캡처한 값을 넣습니다.
3. `.github/workflows/daily-collect.yml`이 매일 한국시간 오전 7시에 자동 실행되며,
   결과 CSV를 저장소에 자동 커밋합니다. 저장소를 clone/pull하면 최신 데이터를 받을 수 있습니다.
4. 지금 바로 한 번 돌려보고 싶다면 저장소의 **Actions** 탭 → `웹소설 랭킹 매일 수집` →
   **Run workflow** 버튼으로 수동 실행할 수 있습니다.

서버를 따로 켜둘 필요 없이 완전히 무료로 운영 가능합니다.

## 5. 사이트로 보기 (GitHub Pages)

저장소 루트의 `index.html`이 `output/webnovel_ranking.csv`를 읽어서
날짜별·플랫폼별로 필터링하고 검색할 수 있는 페이지를 보여줍니다. 별도 서버나
데이터베이스 없이 정적 파일만으로 동작합니다.

**활성화 방법 (최초 1회):**

1. 저장소 **Settings → Pages**로 이동
2. **Build and deployment → Source**를 **"Deploy from a branch"**로 설정
3. **Branch**를 `main`, 폴더를 `/ (root)`로 선택 → **Save**
4. 1~2분 뒤 `https://<사용자명>.github.io/<저장소명>/` 주소로 접속하면 사이트가 뜹니다.

이후로는 GitHub Actions가 매일 CSV를 커밋할 때마다 사이트도 자동으로 최신 데이터를 보여줍니다
(사이트를 다시 만들거나 배포할 필요 없이, 페이지를 새로고침하면 그날 데이터가 그대로 반영됩니다).

- **날짜 탭**으로 하루씩 넘겨볼 수 있고
- **카카오페이지 · 리디북스 · 네이버시리즈 3개 열**이 나란히 보여서 같은 날 세 플랫폼
  순위를 한눈에 비교할 수 있고
- **검색창**에 작품명·작가명·키워드로 검색하면 3개 열 전체에서 동시에 필터링됩니다
- **작품 제목을 클릭**하면 그 작품만 따로 모아 보는 상세 페이지로 이동합니다.
  날짜별 지표값(뷰수/다운로드수/리뷰수) 변화가 그래프로 보이고, 아래엔 날짜별 원본
  수치 표도 함께 나옵니다. 단, **그 작품이 TOP15 안에 들었던 날짜만** 기록되므로
  순위권 밖으로 빠진 날은 그래프에 빈 구간이 생길 수 있습니다.
  (카드 오른쪽 위 ↗ 아이콘을 누르면 원래 플랫폼의 실제 작품 페이지로 이동합니다.)

private 저장소도 GitHub Pages 자체는 무료로 켤 수 있지만, 페이지 내용은 인터넷에
공개됩니다 (링크를 아는 사람은 누구나 볼 수 있음). 완전히 비공개로 두고 싶다면
GitHub Pages 대신 로컬에서 `output/webnovel_ranking.csv`를 엑셀로 열어보는 것을
권장드립니다.

## 6. 네이버시리즈 "매일10시무료" 로맨스 신작 추이 (별도 데이터셋)

`npm run collect`를 실행하면 기존 TOP15 랭킹 수집에 더해서, 네이버시리즈의
**"매일10시무료(FREEFROMTODAY)" 목록 전체를 최신순으로 끝까지 훑어** 그중
**로맨스 장르 + 신작("신규" 뱃지)** 인 작품만 골라내고, 다운로드수·댓글수·별점을
매일 기록합니다. 매일 실행하면 날짜별로 계속 쌓여서 추이를 볼 수 있습니다.

- `output/naver_dailyfree_romance_new.csv` — 실행할 때마다 누적되는 전체 이력
- `output/daily_romance/YYYY-MM-DD.csv` — 그날 하루치 스냅샷

컬럼: `확인날짜, 작품명, 작가명, 론칭일, 별점, 댓글수, 다운로드수, 키워드, URL`

**사이트(대시보드)에서 보기**: `index.html` 상단 탭에 **"매일10시무료 로맨스 신작"** 메뉴가 추가되어
있습니다. TOP15 보드처럼 날짜를 넘겨가며 볼 수 있고, 작품 제목을 클릭하면 그 작품의 별점·댓글수·
다운로드수 추이 그래프가 각각 따로 그려지는 상세페이지로 이동합니다 (지표 3개가 값 범위가 많이
달라서 — 별점 0~10, 다운로드수는 훨씬 큼 — 그래프를 하나로 합치지 않고 세 개로 나눠 보여줍니다).
검색창에서 작품명을 검색해도 이 데이터셋까지 같이 검색되어, 클릭하면 바로 이 상세페이지로 이동합니다.

**알아두어야 할 것**
- 목록 페이지 자체(1,000개 이상)를 페이지네이션 따라 전부 조회하고, 그중 "신규" 뱃지가
  붙은 작품만 상세페이지를 추가로 조회합니다. 신작 개수를 미리 제한하지 않으므로, 그날 새로
  올라온 신작이 많으면 실행 시간이 길어질 수 있습니다.
- "신규" 뱃지가 붙은 작품이라도 로맨스 장르가 아니면(상세페이지 `#로맨스` 키워드 없음)
  최종 결과에서 제외됩니다.
- 이 목록의 정렬(최신순)은 "매일10시무료 프로모션에 편입된 시점" 기준으로 보이며
  작품 자체의 신작 여부와는 무관하게 섞여 나옵니다. 그래서 중간에 멈추지 않고 목록
  전체를 다 훑습니다 — 사이트 구조가 바뀌어 이 가정이 깨지면 결과가 누락될 수 있으니,
  가끔 사이트에서 직접 눈으로 확인해 검산해주시길 권장합니다.
- `#로맨스` 판별은 상세페이지 `<meta name="description">`에 실제로 확인된 방식(TOP15
  스크레이퍼와 동일)이라, 사이트가 이 메타 태그 구성을 바꾸면 오탐/누락이 생길 수 있습니다.
- 대시보드는 이 CSV가 아직 한 번도 생성되지 않았어도(=`npm run collect`를 한 번도 안 돌렸어도)
  에러 없이 "아직 표시할 데이터가 없습니다" 안내만 보여줍니다.

## 7. 데이터가 꼬였을 때 (한 번만 정리)

같은 날짜에 워크플로우를 두 번 이상 돌린 적이 있다면(예: 버그 수정 전/후로 각각 실행),
`output/webnovel_ranking.csv`에 같은 날짜의 옛날 데이터와 새 데이터가 섞여 있을 수 있습니다.
(이 문제는 이제 코드 수정으로 재발하지 않지만, 이미 쌓인 파일은 한 번 정리해줘야 합니다.)

로컬에서 저장소를 pull 받은 뒤, 아래 명령으로 한 번만 정리하면 됩니다:

```bash
npm run dedupe
```

같은 (확인날짜, 플랫폼, 순위) 조합이 여러 번 있으면 **가장 나중에 기록된 것만** 남기고
정리합니다. 정리 후 몇 행이 지워졌는지 콘솔에 출력됩니다. 정리된 `output/webnovel_ranking.csv`를
다시 저장소에 올려주세요 (`Add file → Upload files`로 그 파일만 올려도 됩니다).

## 9. 알아두어야 할 것

- **사이트 구조가 바뀌면 스크립트가 깨질 수 있습니다.** 특히 리디북스는 목록(베스트셀러) 페이지는
  `__NEXT_DATA__` 기반, **개별 책 상세페이지(`/books/{id}`)는 `<script>`에 심어진
  `var bookDetail = {...}` / `var seriesBookListJson = [...]` 기반**으로 서로 다른 방식을 씁니다
  (실측 확인됨. 론칭일은 이 두 변수의 `pub_date`/`reg_date`/`open_date` 중 가장 이른 날짜를 씁니다).
  이 구조가 없는 페이지를 만나면 예전 방식(라벨 근접 탐색 → `__NEXT_DATA__`)으로 자동 폴백하지만
  완벽하지 않을 수 있습니다. 실행 로그에 `[리디북스] __NEXT_DATA__를 찾지 못해...` 경고가 뜨면
  결과를 한 번 검산해주세요.
- 각 상세페이지 조회 사이에 0.5초 딜레이(`REQUEST_DELAY_MS`)를 두었습니다. 서버 부담을 줄이기
  위한 최소한의 배려이니 임의로 줄이지 마세요.
- 이 수집은 **내부 편집 업무 참고용**으로, 하루 1회·플랫폼당 15건 수준의 소량 조회를 전제로
  설계했습니다. 각 사이트의 이용약관을 확인하시고, 대량/고빈도 수집으로 확장하지 않는 것을
  권장합니다.
- 카카오페이지 API나 사이트들의 봇 차단 정책이 강화되면 요청이 막힐 수 있습니다. 이 경우
  User-Agent 조정이나 실제 로그인 세션 쿠키 사용이 필요할 수 있습니다.

`npm test`로 파서/화면 로직에 대한 자동 테스트를 돌릴 수 있습니다 (실제 사이트 접속 없이,
저장해둔 샘플 HTML로 검증합니다):

```bash
npm install

```

사이트 구조가 또 바뀌어서 이 리포지토리를 다시 고치게 되면, 그때 캡처한 새 샘플 HTML로
`test/sample_*.html`을 갱신하고 `npm test`로 확인해보시는 걸 권장합니다.

## 10. 폴더 구조

```
webnovel-ranking-collector/
├─ index.html                # GitHub Pages로 여는 대시보드 (5번 참고)
├─ robots.txt                 # 검색엔진 색인 차단
├─ src/
│  ├─ collect.js            # 실행 진입점 (3사 순회 → CSV 저장)
│  ├─ scrapers/
│  │  ├─ kakaopage.js
│  │  ├─ ridibooks.js
│  │  ├─ naverseries.js
│  │  └─ naverseries-dailyfree-romance.js  # 매일10시무료 로맨스 신작 추이 (6번 참고)
│  └─ lib/
│     ├─ http.js            # fetch 래퍼, 정규식 유틸(해시태그/별점/날짜 추출)
│     ├─ csv.js              # CSV 저장(당일 데이터 교체) 및 파싱 (TOP15용 + 로맨스신작용)
│     └─ deepFind.js         # __NEXT_DATA__ 안에서 목록 배열/날짜 필드 찾기
├─ scripts/
│  └─ dedupe-csv.js          # 기존에 꼬인 CSV 한 번 정리하는 스크립트 (6번 참고)
├─ .github/workflows/daily-collect.yml
├─ .env.example
└─ output/                   # 실행 결과가 여기 쌓입니다 (index.html이 이 폴더를 읽음)
```
